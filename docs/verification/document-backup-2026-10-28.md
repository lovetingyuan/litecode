# 文档增量同步与分文件备份验证（2026-10-28）

修复项目审计问题 1：编辑一个文档时，原实现读取并通过 IPC 发送全部打开文档的正文，再序列化和 fsync 整个会话。

## 实现与恢复策略

- 前端 `DocumentBackups` 只记录确认成功的模型身份、版本和元数据，不保留第二份正文。首次同步及正文变化才调用 `getValue()`；省略 `text` 表示复用后端内存正文，空字符串仍表示真实空文档。
- 快照在现有串行队列内生成；成功落盘后才确认版本。普通文档等待空闲 400ms，大文件等待空闲 2 秒，分别计时；延迟中的文档沿用已确认快照，新文档等首次期限后加入。
- 启动恢复直接确认 bootstrap 已有的后端镜像，避免恢复的大文件在首次空闲期限前被移出清单，也不再将已知正文传回后端。
- 显式 checkpoint 立即同步全部待同步变化。搜索、替换继续使用完整内存镜像；窗口关闭、更新以及文件移动和删除的屏障保持生效。
- `session-<label>.json` 使用 `version: 2`，包含工作区、界面状态、文档元数据及可选的 `body` 哈希引用；元数据中的 `text` 为 null，不包含正文。
- 仅脏文本和无路径文本写入 `recovery/<label>/<SHA-256>.txt`，内容为 UTF-8。只克隆、计算哈希和写入变化的待备份正文；其余正文复用引用。
- 先原子写入并 fsync 正文，再原子提交并 fsync 清单；清单相同则不写盘。成功提交后才清理失效正文，清理失败不撤销已成功的备份。
- 最终窗口刷新与普通备份使用同一窗口的恢复锁串行；最终刷新不等待磁盘排他锁，避免 UI 与文件操作相互等待。
- 启动读取旧内嵌格式和 v2 格式，首次成功提交后迁移。脏文件恢复备份，干净文件读取当前磁盘，缺失或不可读的干净文件提示并跳过。
- 损坏正文或清单会产生警告，原始清单保存在该窗口恢复目录的 `preserved-*.json`，相关正文停止自动清理。若无法保留损坏清单，则阻止覆盖。替换事务日志保持原格式。

## 性能实测

固定场景：8 个约 1 MiB 的干净文本、1 个约 24 MiB 的干净文本、1 个约 4 KiB 的可编辑文本。镜像初始化完成后，连续三次只修改小文档并立即 checkpoint；真实 Windows Tauri / WebView2 运行。

| 指标 | 原实现 | 修复后 |
| --- | --- | --- |
| 每次 IPC 正文数 | 10 | 1 |
| 每次 IPC JSON 字节 | 35,538,715 | 10,377 |
| 每次磁盘变更文件总字节 | 35,539,044 | 10,389 |
| 编辑并完成 checkpoint | 3,522–4,045ms | 115–149ms |
| 未变化文档的模型正文读取 | 所有文档 | 0 |

IPC 和磁盘字节减少约 99.97%。磁盘统计为前后哈希发生变化的文件长度之和，未计相同内容的重复写入及文件系统元数据。延迟包含 Monaco 内容更新、IPC 与落盘，不能直接当作键盘输入延迟。

原实现磁盘/耗时基线：`.verification/document-backup-before-1793173338106/results.json`。该次 Tauri 全局不可替换，IPC 计数为 0，不能采用；随后通过仅在验证页面拦截 bridge 响应测量旧前端，得到 `.verification/document-backup-before-1793174036471/results.json`，两次 IPC 共 71,077,430 字节。后一轮已经使用新后端，仅用于旧前端的 IPC 指标，不用于磁盘和耗时基线。

最终修复后记录：`.verification/document-backup-after-1793176598815/results.json`。三个样本均仅发送一个正文，所有未变化文档正文读取为零，无页面 JavaScript 错误。此前同场景复测为 235–287ms，字节数完全相同；耗时受主机负载影响。验证脚本为 `tools/verify-document-backup.mjs`，输出保留在被 Git 忽略的 `.verification/` 中。

## 保留的限制

- 单个变化文档仍传输和备份完整正文，不包含文档内部差分或操作日志。持续输入期间的自动备份仍等待空闲；显式 checkpoint 不受此延迟影响。
- 干净文件不再保留历史正文；重启读取磁盘当前内容，不能恢复已从磁盘删除的干净文件原文。
- 首次建立内存镜像仍需同步干净正文供搜索和替换使用；它不会写入恢复正文文件。
- v2 兼容读取旧备份，旧版本应用不具备读取 v2 的能力。损坏记录保留目录需要人工检查后再清理。
