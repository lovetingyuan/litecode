# 大项目文件树：按需加载与局部刷新

验证日期：2026-10-21。测试项目：`D:\xiaotian\xiaolesmart-ui`，共 **293,936 个文件和目录项**，根目录可见子项 26 个，`apps/` 直接子项 11 个。遍历不跟随符号链接，并跳过 `.git`。

测试只读取目标项目。结果、便携测试程序和截图均保存在 LiteCode 的 `.verification/` 中；目标项目的 `package.json`、`pnpm-lock.yaml` 和 `.git/index` 在原生验证前后 SHA-256 相同。Git 查询显式设置 `update_index(false)`。

## 行为与接口

- `read_workspace_directory({ directory, expectedRoot, session })` 只读取直接子项，返回根路径、会话号、规范目录、路径和警告。校验当前窗口的根目录与会话，拒绝父目录跳转及通过符号链接展开。
- 目录缓存属于一次工作区打开会话；重复展开复用缓存，并发读取合并。读取期间失效时丢弃过期结果并补读，换工作区或删除目录后丢弃迟到结果。额外的前端 epoch 覆盖快速 A → B → A 切换。
- 树按目录批量增删，每 512 个操作让出一次界面线程；不再传输全工作区路径或运行整份树的预处理 Worker。定位文件逐层加载祖先，保留已有展开、选择、焦点和滚动。
- `workspace-changed` 携带根、会话、变化路径、结构变化标记、Git/文件索引变化及恢复标记。350ms 合并窗口、最多 4096 个待处理路径；溢出和不明确事件转为已加载目录的恢复性刷新。
- 内容变化不读取目录；结构变化只刷新相关展开目录，折叠目录标记失效。Git 元数据仍通知 Git 和相关已打开文档。
- `workspace_git_status` 独立异步查询；已知仓库缓存，首次嵌套仓库发现后台执行。异常或不完整结果保留上次 Git 状态。“仅搜索已更改文件”复用仓库查询并在阻塞任务中执行。
- 快速打开使用自己的文件列表版本与设置缓存，保持现有 `rg --files` 及匹配规则。关闭面板时不重建，重新打开复用结果及进行中的枚举；目录展开和普通保存不使它失效。
- 保留树组件版本及已有补丁。新增纯添加节点不取消拖拽的补丁，使拖拽悬停展开能完成异步目录加载；删除和移动仍取消原拖拽会话。

## 实测结果

后端旧流程在同一测试可执行程序中复现原来的 WalkDir 遍历、20 万条截断、嵌套仓库检查与 Git 查询。新流程只读取所需目录。Rust 使用默认 test/debug 配置；重复测量 6 次，下面列出后 5 次的中位数。

| 测量 | 旧流程 | 新流程 |
| --- | ---: | ---: |
| 阻塞目录显示的读取工作 | 全量扫描及 Git：3656.31ms | 根目录读取：0.604ms |
| JSON 序列化 | 769.14ms | 0.045ms |
| JSON 大小 | 22,851,049 字节 | 426 字节 |
| 本次传输的路径项 | 200,000，已截断 | 26，无全项目截断 |
| 展开 `apps/` 的目录读取 | 包含在全量扫描中 | 0.394ms，11 项 |

进程首次根目录读取发生在该进程遍历工作区之前，为 **0.990ms**。未清空操作系统缓存，不能把这个数字称为冷磁盘耗时。后台完整仓库发现首次为 **13.58s**，独立 Git 查询热测中位数 **1134.23ms**；这些成本仍存在，但不再阻塞目录显示，也不会在每次刷新时重做完整仓库发现。

Node/V8 使用同一项目的前 20 万条路径，独立测量树模型准备，3 次中位数如下。此项不包含 DOM 绘制和 IPC。

| 树模型阶段 | 旧流程 | 新流程 |
| --- | ---: | ---: |
| 一次 structured clone | 50.44ms | 无全量路径复制 |
| 路径预处理 | 1408.95ms | 无全量预处理 |
| 模型创建／根目录批量加入 | 202.41ms | 0.817ms |

原生 WebView2 在实际项目上验证：启动只载入根目录；根目录 IPC 约 **6.7ms**，展开 `apps` 的 IPC 约 **10.8ms**；重复展开没有再次读取；模拟内容变化没有目录读取。快速打开首次约 **696ms**、再次打开约 **152ms**，包含测试驱动等待。

该次新进程从启动到测试驱动观察到树可见约 **45.2s**，包含开发服务器模块加载、编辑器服务初始化、WebView2 和 CDP 建连，不是文件树读取耗时；没有旧版整程序启动对照，不能据此声称整程序冷启动的提升倍数。单个拥有大量直接子项的目录仍需枚举和建立这些子项，虚拟渲染与批量应用不能消除这部分工作。

## 回归与证据

- 前端全量单元测试 218 项，后端单元测试 55 项；另单独运行只读性能基准。TypeScript/生产构建及 lint 通过。
- 一次并发生产构建与浏览器回归期间，未改动的 Monaco 语法加载测试触发 5 秒超时；待并发负载结束后以两个 worker 重跑全套测试，不修改测试超时或跳过用例。
- 文件定位、大小写路径、新文件等待、视图隐藏、手动刷新、逐帧展开和滚动保持、工作区切换及迟到结果。
- 多选拖拽、悬停展开、边缘滚动、冲突与取消、部分移动失败、脏编辑器路径重绑定及保存队列；文件树到编辑器的实际鼠标拖放。
- 原生 Git 忽略、否定规则、嵌套规则变化、分组编辑器标记与分支／Git 状态独立查询。
- 快速打开的 1 万、5 万、20 万文件场景，包括输入、排序、高亮、Enter、取消、重新打开、设置变化和 IME。

原始测量：`.verification/lazy-explorer/existing-backend.json`、`model.json`；原生只读项目验证：`.verification/large-explorer-1792580486605/results.json` 和 `tree.png`。测试使用开发构建，存在其他进程与磁盘缓存影响；以上是观测值，不是延迟保证。
