## P1：优先修复

### 1. 单独打开 Vue 文件可绕过工作区执行信任

- **严重程度**：P1 / 高。
- **代码位置**：[state.rs:220](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/state.rs:220)、[languages.ts:255](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src/editor/languages.ts:255)、[tools.rs:186](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/tools.rs:186)。
- **问题描述**：没有工作区根目录时，语言服务仍被允许启动。随应用提供的 Vue 工具链会发现单独打开文件附近的 `tsconfig.json`，并通过 `require()` 加载 `vueCompilerOptions.plugins`。因此，打开带有恶意项目插件配置的 Vue 文件，可能在没有经过工作区执行信任确认的情况下执行本地 JavaScript。
- **验证依据**：已通过内存拦截确认实际打包工具链的插件加载路径；未在完整桌面应用中执行攻击验证。
- **初步解决方案**：对单独打开或位于已信任工作区之外的文件实施执行信任检查；未获信任前禁用项目插件，或仅提供不加载项目代码的受限语言服务。增加单文件、工作区外文件和父目录配置发现的回归测试。
- **解决难度**：中，需要统一前后端对单文件与工作区外文件的信任语义。
- **影响范围**：Vue 语言服务及其项目插件，执行权限可达到应用当前用户权限。

### 2. WebView 重载或启动期间关闭可能清空恢复数据

- **严重程度**：P1 / 高。
- **代码位置**：[App.tsx:228](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src/components/App.tsx:228)、[documents.ts:301](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src/editor/documents.ts:301)、[state.rs:356](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/state.rs:356)。
- **问题描述**：关闭处理器在前端恢复文档状态完成前就可能运行。WebView 重载后，原生层仍保留未保存文档镜像，但前端暂时没有文档；此时关闭可提交空文档快照。原生同步会删除快照中缺席的镜像，随后恢复清理逻辑可能清除正文，导致本来可恢复的未保存内容丢失。
- **验证依据**：前端模拟探针确认空快照时序，原生删除与恢复清理后果由源码追踪确认；未做完整桌面端到端复现。
- **初步解决方案**：只有文档恢复初始化完成后才允许提交最终全量快照；初始化失败或尚未完成时保留原生恢复数据。使用显式恢复状态区分“确实没有文档”和“尚未加载文档”。
- **解决难度**：中，涉及关闭流程、恢复状态及前后端同步契约。
- **影响范围**：未保存文档、WebView 重载、启动异常和崩溃恢复。

### 3. 剪切链接目录时移动了真实目标

- **严重程度**：P1 / 高。
- **代码位置**：[commands.rs:698](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/commands.rs:698)。
- **问题描述**：旧剪切路径先将源路径规范化为真实路径，再执行重命名，与较安全的拖动移动校验不一致。剪切 Windows junction 等链接目录时，操作对象会变成链接指向的真实目录，导致真实目标被搬走，原链接留在原处且失效。
- **验证依据**：隔离 Windows junction 探针确认真实源目录消失、链接残留失效、目标数据被移动。
- **初步解决方案**：复用已有安全移动流程；在规范化解析之前拒绝链接以及经过链接祖先目录的路径，统一剪切和拖动移动的文件身份校验。
- **解决难度**：中，需要覆盖链接、跨目录移动及失败回滚。
- **影响范围**：资源管理器剪切粘贴、链接指向的数据和文件系统完整性。

### 4. 原子保存未保留 Windows ACL

- **严重程度**：P1 / 高。
- **代码位置**：[files.rs:125](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/files.rs:125)。
- **问题描述**：原子写入只复制 Rust 基础文件权限，未保留 Windows 安全描述符和 ACL。临时文件替换原文件后，受保护文件可能改为继承父目录权限；在共享或权限较宽的目录中，这可能扩大敏感文件的访问范围。
- **验证依据**：使用项目实际 `atomic_write` 的隔离探针显示，保存前 ACL 为受保护且包含 1 条 ACE，保存后变为非受保护且包含 4 条继承 ACE。
- **初步解决方案**：在替换时保留原安全描述符，并在写入正文前限制临时文件权限，避免临时阶段暴露。增加显式 ACL、禁用继承和共享目录场景的 Windows 测试。
- **解决难度**：中，需要 Windows 原生权限处理及平台专属回归测试。
- **影响范围**：所有使用该原子写入路径的操作，包括普通保存和批量替换。

### 5. 声称不覆盖的重命名存在检查与使用之间的竞态

- **验证依据**：Windows 隔离探针确认 `fs::rename` 可以覆盖已存在的目标文件；完整并发窗口由代码顺序确认。
- **初步解决方案**：复用已有操作系统级原子 `rename_no_replace`，覆盖提交与回滚路径，避免使用存在性预检查代替原子保证。
- **解决难度**：低。
- **影响范围**：外部文件拖入、旧剪切粘贴路径及相关回滚，可能覆盖并发创建的文件。

### 6. 自动备份失败后不再空闲重试

- **严重程度**：P2 / 中。

- **初步解决方案**：保留未确认快照并进行有上限的退避重试；关闭、销毁和新快照到来时正确取消或合并重试。
- **解决难度**：低。
- **影响范围**：未保存文档的自动备份与异常退出恢复。

### 11. 批量替换日志产生平方级写放大

- **严重程度**：P2 / 中。

- **问题描述**：事务日志同时保存全部文件的替换前后正文，每完成一个文件都重新序列化、写入并同步整份日志。文件数增加时，进度更新产生接近平方级的写放大，拖慢大规模替换、撤销和重做。

- **初步解决方案**：不可变正文只持久化一次，将进度存储为小型追加日志或独立状态文件；明确崩溃恢复时的数据落盘顺序。
- **解决难度**：中至高，需要调整持久化结构并验证中断恢复。

### 15. 文件监听误过滤普通 `.lock` 文件

### 16. 仅搜索变更文件仍扫描全仓库，并可能被无关文件截断

- **严重程度**：P2 / 中。
- **代码位置**：[search.rs:301](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/search.rs:301)。
- **问题描述**：变更文件模式仍对 `.` 执行 ripgrep 全仓库扫描，在有界读取和 JSON 解析之后才过滤允许的路径。因此未变更文件也消耗搜索时间和输出预算；无关文件产生超大事件时，还会提前终止本应仅针对变更文件的搜索。
- **验证依据**：隔离仓库中，未变更文件产生 9,437,372 字节的事件，超过 8,388,608 字节上限，导致搜索停止；正确限定目标后的输出仅 745 字节。
- **初步解决方案**：将符合条件的路径直接传给 ripgrep，按命令行长度限制分批执行；目标为空时直接返回，并统一合并批次结果和取消信号。
- **解决难度**：中。
- **影响范围**：变更文件搜索的完整性和大仓库搜索性能。

### 17. 格式化超时未终止后代进程

- **严重程度**：P2 / 中。
- **代码位置**：[tools.rs:485](/C:/Users/huangbt1/Downloads/litecode-main/litecode-main/src-tauri/src/tools.rs:485)。
- **问题描述**：`kill_on_drop(true)` 只保证直接子进程被终止，不能保证终止它启动的后代进程。格式化器包装脚本或插件派生的工作进程，可能在 30 秒超时后继续运行，并在重试时累积或继续产生后台副作用。
- **验证依据**：静态检查进程生命周期和超时清理路径；未进行完整桌面进程树复现。
- **初步解决方案**：Windows 使用 Job Object 管理整棵进程树，并在超时、取消及异常退出时统一终止；其他平台使用相应进程组机制。增加派生工作进程的清理测试。
- **解决难度**：中。
- **影响范围**：外部格式化器、后台进程数量、CPU 和内存占用，以及超时后的后台操作。
