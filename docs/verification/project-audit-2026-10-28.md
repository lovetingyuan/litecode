## P2：中优先级

### 8. 前端核心文件过大，状态逻辑过于集中

- **位置**：`src/editor/documents.ts`（约 1474 行）、`src/components/Explorer.tsx`（约 1215 行）、`src/core/commands.ts`（约 1047 行）、`src/components/GitView.tsx`（约 1002 行）；后端 `src-tauri/src/git.rs`、`src-tauri/src/workspace.rs` 也接近 1000 行。
- **问题说明**：`documents.ts` 同时负责模型、保存队列、移动屏障、备份和自动保存，依赖大量模块级可变状态（多个计时器、`checkpointQueue`、`saveQueues` 等）。
- **影响**：并发时序难以推理，修改容易引入回归，单元测试难以覆盖。
- **初步解决方案**：按职责拆分为保存、备份恢复、文档移动、模型注册等模块；为队列和屏障逻辑补充单元测试；大型组件按子视图拆分。
- **复杂度**：中高，建议分阶段进行。

## P3：低优先级

### 9. 二进制工具和验证产物直接入库

- **位置**：`src-tauri/tools/rg.exe`；`docs/verification/ui/` 下的截图和多份 JSON 报告。
- **问题说明**：二进制文件和生成产物直接提交到 Git。
- **影响**：仓库体积持续增长；二进制来源不易审计。
- **初步解决方案**：由 `build:tools` 下载 ripgrep 并校验哈希，或改用 Git LFS；验证产物改为 CI artifacts。
- **复杂度**：低。

### 10. 代码块高亮依赖 `dangerouslySetInnerHTML`

- **位置**：`src/components/MarkdownPreview.tsx`（约第 212 行）。
- **问题说明**：HTML 来自 `monaco.editor.colorize`。Monaco 会转义输入，目前是安全的。
- **影响**：安全性依赖第三方库的实现细节，升级 Monaco 时可能悄然失效。
- **初步解决方案**：先经 DOMPurify 过滤，或添加注释并补充包含 `<script>` 等内容的回归测试，固定这一假设。
- **复杂度**：低。

## 建议修复顺序

2. **问题 9、10**：改动相对独立，可穿插处理。
